# 会话、额度与模型协议（阶段交付）

## 已实现边界

学生本人会话创建、分页/标题检索/白名单排序、详情、CAS软删除已可调用。查询重新核对当前订单学生归属和订单状态；中介没有私聊访问权。创建与删除保持账户、订单、会话的锁顺序。会话列表没有状态字段，因此删除设计稿机械附加的status过滤；传入status明确返回400。

`GET /api/v1/student/quota`返回真实数据库账户投影。模型运行、消息提交、持久化SSE回放、管理端核对接口尚未接通，不能据此宣称已能在线答疑。

## 月额度与账务规则

- 采用UTC自然月边界，会员首次访问或预占时懒授予该月额度，不按剩余天数折算。此规则是本轮实现决策，前端须展示实际periodEnd。
- 同月续期或重复授予不重复增加额度；升级只补足该月已经授予上限的正差值，词元与人民币金额分别计算。降级不追溯扣除已授予值，会员撤销/到期后禁止新预占，查询可用额度为0，已有冻结仍展示。
- 使用数据库事务起点确定月周期，避免初始化与查询跨月不一致。账户行锁串行裁决多节点并发预占；账户更新和追加式账本在同一事务。唯一run_id保证运行不能重复预占；相同运行不同参数返回冲突。金额单位CNY，数据库保留6位小数。
- 输入总词元包含缓存部分，费用按非缓存输入、缓存输入和输出分别计价，合计后按人民币小数6位向上取整。结算以预占时固定价格ID计算，生效价格不可覆盖。
- 实际用量超过预占仍完整记账，可用额度下限为0，不能因余额不足丢弃供应商成本。跨月结算回到原冻结账户。
- 断流、超时、缺少供应商用量、进程失联必须保留RECONCILING冻结；可信业务确认无费用后才能释放。当前release方法只供内部服务调用，没有接受学生自报无费用的接口。
- 账本禁止UPDATE/DELETE，纠错应以今后的授权调整记录追加。管理员调整、核对证据与过期冻结运维入口尚未实现。

## 供应商适配

`ModelGateway`提供同步流回调，调用者必须在数据库事务之外发请求，增量回调应独立短事务保存。当前实现OpenAI兼容Chat Completions文本流，要求`stream_options.include_usage`、最终usage和[DONE]，不会把缺失用量当作0，也不会自动重试请求。

默认`ZX_MODEL_CALLS_ENABLED=false`，即使管理端保存了密钥也不会发出模型请求。正式启用还需`ZX_MODEL_ALLOWED_HOSTS`精确主机白名单、HTTPS完整Chat Completions端点及启用的模型/密钥/有效价格。端点不是base URL，不接受查询串、用户信息或片段，不跟随重定向。白名单需由可信部署人员维护，并配合网络出口策略。

适配器限制连接5秒、读取30秒、总调用180秒，单事件64KiB、累计输出262144字符、输出上限8192词元。供应商不同协议/更大输出目前须新增适配与测试；不能仅填入任意provider名称就认为支持。错误仅保留稳定代码，禁止记录密钥和供应商原始正文。

本轮协议测试使用临时127.0.0.1确定性HTTP服务，验证增量、缓存词元、断流未知、429拒绝及默认关闭。没有真实供应商调用或费用。

官方协议依据：[流式响应](https://developers.openai.com/api/reference/resources/chat/subresources/completions/streaming-events)、[创建Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。最终用量可能因流中断而缺失，需通过核对恢复，不能盲重发。

## 后续接入约束

实现model_run后为quota_hold.run_id补外键；当前预占仅供内部服务和隔离测试使用。运行创建须在同一事务选定有效价格、预占、保存唯一clientMessageId和上下文/引用快照。外部调用前持久化调用状态，崩溃后不能重复发出已开始的调用。补齐持久事件序号、回放、取消、权限重查和核对证据之后再对外开放消息提交。

## 下一阶段契约核对记录

设计字段字典使用`generation_run`与`run_event`，应沿用该命名；运行状态与计费状态为两个维度，`FAILED + RECONCILING`是有效组合，不能把业务失败等同于账务释放。当前已有`quota_hold`状态枚举与契约billingState一致。

发现待运行阶段一起修订的限制：设计`chat_message.text`为varchar(20000)，而8192输出词元并不能保证只有20000字符，网关当前字符防护上限为262144。落库前必须统一消息/API/流事件大小限制，建议消息正文使用text并通过明确字节/字符上限约束，不能截断正文后继续宣称完整答复。

创建运行的固定顺序应与现有写入锁保持一致：身份账户→订单→会话→额度账户→运行/预占。运行结束只锁额度账户再锁运行/预占，不反向获取订单锁。流回放只能读持久事件，不得触发模型调用或新增预占。租约失效后，尚未开始的任务可重领；已有外部调用标记的任务进入核对，不能将资产扫描任务的自动重试规则直接复用于付费模型。

以上是后续实施约束，不代表运行表、回放或对账已实现。继续开发时需以真实并发测试确认锁顺序与取消/结算竞争。
