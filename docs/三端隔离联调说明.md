# 三端隔离联调

此流程仅在本机隔离数据库中验证业务，不使用业务数据或真实短信。所有随机凭据、验证码和私钥存放secrets下的0600文件，不提交。

1. 停止本任务拥有的18080验证API后，执行`python3 scripts/start-ui-verification.py --test-sms`。创建新的zx_ui_前缀数据库、正式迁移、受控管理员邀请和MFA激活，API使用正常认证逻辑。
2. 本机18443提供隔离HTTPS短信协议服务，仅接受13900009990至13900009999测试号码，无外部供应商连接。使用临时证书和独立Java信任库，不修改系统信任、不跳过TLS校验。验证码仅写受保护文件，页面仍调用正式验证码接口。
3. 执行`python3 scripts/prepare-ui-accounts.py`通过正式注册与中介邀请激活API创建测试账户。测试条款版本ui-test-nonbinding仅用于这个独立环境，不代表生产服务协议已准备好。脚本针对新库执行一次，不是生产初始化工具。
4. 执行`python3 scripts/prepare-ui-business.py`创建测试院校、专业、未收款已确认订单、项目和需审核板块。脚本也仅用于新库，失败后先检查已创建记录，不能反复盲重放。
5. 执行`python3 scripts/start-ui-worker.py`建立同名独立RabbitMQ vhost并启动隔离库worker，绝不消费业务vhost队列。数据库任务由正常租约和状态机执行，ClamAV保持真实扫描。
6. 上传前须在管理页面新增存储配置，并将当前库该配置ID写入受保护目录runtime-overrides.json的ZX_UPLOAD_STORAGE_ID。`--test-sms --resume`复用当前验证数据库，避免重建账户；覆盖项仅允许上传配置ID。HMAC固定保存到本库受保护文件，后续重启保持手机号摘要及MFA秘密可读，已有刷新会话按正常过期策略处理。早期脚本未保存原始HMAC，不能恢复该验证库认证；现在恢复时缺少密钥会明确拒绝，必须创建新的隔离验证库。原始库保留为历史测试证据，不修改其认证数据。

当前数据库、API PID和凭据文件位置以docs/ui-verification-state.json为准。worker PID在同目录worker-state.json。旧隔离库保留作为验证证据，不清空业务卷；清理必须按确切名称和本脚本记录的对象范围执行。

已实际验证：三端正式账户准备；浏览器学生登录/刷新/资料编辑、一次性订单绑定、项目可见、发帖待审核；管理员审核发布；学生回复；中介登录及名下学生列表，手机号脱敏。隔离worker已启动且日志无ERROR。附件上传、全量业务和生产集群还不能认定验收完成。
