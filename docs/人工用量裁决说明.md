# 人工用量证据裁决

当原模型调用没有返回可信用量，且供应商未提供可查询接口时，RECONCILING冻结不能凭一句原因自动释放。新增独立人工裁决单：第一位管理员提交USAGE或NO_CHARGE、供应商账单/工单引用、原始凭据SHA-256和理由；另一位拥有billing:adjudicate权限的管理员独立核验后批准或拒绝。

服务器保存的是人工声明和复核责任链，不会自动访问引用URL，也不能仅凭摘要证明文件真实性。原始凭据应由业务方保存，复核者独立检查文件摘要、供应商账户、请求标识及计费周期。人工证据不写入run_usage_evidence，账单和CSV明确显示人工来源。

## 接口

- POST /api/v1/admin/runs/{id}/adjudications：提交待审核单，201；不改变冻结余额。同运行只能有一个PENDING。
- GET /api/v1/admin/adjudications：page/size分页，可按runId/state筛选，固定提交时间倒序。
- GET /api/v1/admin/adjudications/{id}：详情、版本、来源和disputed标志。
- POST /api/v1/admin/adjudications/{id}/decision：独立审核APPROVE/REJECT，必须幂等键与强If-Match；禁止自审。

所有接口仅管理员，方法权限及服务层当前权限双重校验。新增权限由受控超级管理员角色拥有，其他角色需显式授予。凭据字段仅管理员可读，不放入学生账单。

## 事务与冲突

统一按账户→运行→裁决单→预占加锁。批准时重新检查RECONCILING且没有原调用证据，然后按运行原价格结算，或对明确NO_CHARGE释放。裁决终态、账本、审计和outbox同事务；同版本并发批准只成功一次。拒绝保留冻结，之后可重新提交；凭据及终态不能修改或删除。

原调用证据在批准前到达时拒绝人工批准，要求走既有可信核对。批准后才到达且不一致时，详情disputed=true，原证据和人工记录都保留，不重新发布回答、不自动覆盖已结算账本。财务需要复核差异，已有金额调整入口只能修正金额，词元争议不能通过静默改库处理，需后续受控更正方案。

## 验证与边界

74项测试全部通过（扩展现有集成场景），包含真实数据库、自审拒绝、双人批准/拒绝、并发CAS、仅一次结算/释放、凭据不可变、迟到原证据和争议标记、账单来源及跨端拒绝。契约1.0.24，共247操作；新增4个裁决操作不属于原243基线，不得用比例代替交付完成度。

供应商账单查询没有统一协议；当前仍仅原调用可信返回和人工双人复核，不伪造外部查询成功。付费模型和外部短信默认关闭，本轮没有真实付费调用。
