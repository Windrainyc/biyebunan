# 统计与导出接续约束

本文件是下一阶段实施依据，不代表接口已实现。

现有V25 event_activity_day只包含日期、事件类型和数量，是全局活动投影，缺少actor、订单和中介归属，不能直接当作学生或中介统计。消费者inbox去重不等于所有业务指标已完成。中介范围必须以当前订单partner_id为依据，不能从客户端传入身份，也不能统计私聊或模型用量。

建议先在同一只读数据库快照中实现有界日期范围统计，明确北京时间日边界、from/to包含性和最大窗口。订单数量/金额按创建日，交付按实际发布事件，词元/金额按真实已结算账本时间；未知用量单独展示，不能按零成本算入。金额与调整应分列，不能把订单金额当已收款。若直接查数据库且无异步投影，lagSeconds=0只能表示读取方式，generatedAt应与快照关联，不宣称无事务延迟。

活跃用户必须明确业务活动定义，不能把全部outbox事件数或系统worker操作当真实用户数。首次落地须同时输出指标字典、权限范围和测试证据。

异步导出应冻结请求参数与申请身份，worker执行和下载时重验当前权限/归属；禁止以申请时权限永久放行。私有对象关联导出任务、有效期和下载日志，结果未生成不得返回下载链接。中介任务详情仅能查看本人申请的、当前仍有权的内容。导出数据和私聊字段必须白名单，CSV需处理公式注入。复用现有任务租约与对象存储端口，不建立无状态内存任务或公开桶。
