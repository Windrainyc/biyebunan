# 编辑、预览与RabbitMQ接入开发方案

日期：2026-10-30。用户已授权先写方案再直接开发，无需二次审批。

## 目标与范围

1. 知识库Markdown正文接入Tiptap可视化编辑，保留源码编辑、既有Markdown存储、发布快照、服务端可见范围与权限。首期工具栏覆盖标题/段落、粗体、斜体、列表、引用、代码、撤销重做。不得将HTML直接塞入markdown字段；不引入ONLYOFFICE。
2. 独立Docker部署kkFileView，接入Office附件预览；原图片、PDF、文本、MP4预览继续使用已有轻量组件。预览只针对READY且当前用户有权访问的素材；转换不公开对象存储，预览缓存不得绕过授权。失败有明确状态，原文件下载仍可用。
3. 复用现有RabbitMQ、outbox、数据库任务和worker，补齐通知消费者与必要业务触发，并检查扫描、知识索引、导出、视频和模型任务是否适合消息唤醒。队列只携带事件或任务标识，不放私密正文或凭据。

## 已核对的实现

- OutboxPublisher已实现持久消息、mandatory、publisher confirm、租约及generation保护；ActivityListener独立统计订阅、数据库核对本库outbox、inbox去重，提交后ACK。
- NotificationService.enqueueDelivery与交付发布同事务写notification_delivery_task；NotificationWorker每5秒轮询，当前没有Rabbit消费者。收件箱唯一键为recipient_id/event_id，已读单向幂等。优先接入Rabbit消息按event_id投递，并保留低频补偿。
- AssetWorker、IndexWorker、EmbeddingWorker已有数据库领取/状态约束。消息只作唤醒，数据库仍决定任务可否执行；不把消息存在当任务成功。
- 素材下载当前为60秒私有签名附件，不能直接把存储地址交给公开kk页面并允许任意URL转换；需建立受控访问边界。运行环境为独立UI数据库和隔离Rabbit vhost，禁止消费其他业务队列。
- 前端MaterialMedia已有PDF.js、图片Blob预览、视频首帧；MarkdownContent为受控渲染，SchemaField正文仍是textarea。

## 分阶段实现

### A 编辑器

锁定Tiptap Vue3/StarterKit/Markdown扩展兼容版本，新增KnowledgeEditor。Markdown作为唯一持久数据，编辑器读写不破坏既有内容；不支持的源格式保留源码编辑，切换须防止静默丢失。表单错误、空正文、编辑回显、保存/发布后阅读验证。

### B 私有Office预览

先核实kkFileView官方版本、镜像架构及配置。独立本地容器、固定版本、限定来源及缓存目录；应用侧先验权，服务间访问使用短时授权。预览页面、转换输出及缓存访问均受控，不能只保护入口而留下公开缓存。优先复用已有存储端口，不允许用户输入任意下载URL；对转换设置大小/时间上限。配置缺失返回显式不可用，不静默成功。若官方服务无法满足直接安全嵌入，采用隔离转换后将预览产物回存私有存储的方式，避免公开转换服务。

### C RabbitMQ与通知

独立通知订阅队列绑定既有事件交换机，不抢统计/任务队列。消费者核对本库outbox真实性；只处理本事件已持久化的通知任务；数据库提交后ACK，重复投递无新增通知。失败进入独立死信，保留低频数据库补偿。检查订单归属、项目阶段/交付、内容审核、素材扫描/预览失败等适合通知的业务；接收人由服务器关系决定，通用安全文案不泄露私聊与项目正文。模型任务仅按现有可恢复状态领取，付费调用已开始或未知时禁止重新执行。

### D 验证与交付

编辑器单测/类型构建；后端真实Rabbit集成验证首次/重复/伪造消息与数据库恢复；Office真实测试文件转换和越权拒绝；浏览器新增/编辑知识、附件预览、通知读取。依次执行Java格式/分层/JavaDoc、契约校验、相关测试、本地启动。分别记录源码、测试、容器及生产边界。只本地中文提交，不推远程，不生产部署。

## 实施决策与业务接入矩阵（2026-10-30）

| 流程 | 本次处理 | 原因与恢复方式 |
|---|---|---|
| 订单绑定成功 | 同事务保存学生通知快照，RabbitMQ触发 | 归属证明只消费一次，通知失败不回滚已提交业务，不重复创建通知 |
| 项目阶段推进/验收 | 同事务保存学生通知快照，RabbitMQ触发 | 仅收件人可见通用进度提示，不把原因/私聊传给中介 |
| 交付发布 | 复用既有模板快照，改为RabbitMQ主触发 | 模板停用仍抑制发送；持久数据库任务每60秒兜底 |
| 统计订阅 | 继续使用既有独立Rabbit队列 | 不抢占通知队列；原outbox/inbox规则保留 |
| 资产扫描、知识索引、视频、导出 | 保留已有持久任务、租约与worker | 已是异步且可恢复；此阶段不为了使用MQ增加第二套调度状态 |
| 模型运行/未知用量 | 保留现有唯一请求与冻结核对 | 已开始外部调用不得因重复消息盲目重发 |
| 过期/保留期/孤立文件回收 | 保留定时扫描 | 本质为时间驱动维护，不应依赖某条消息才能执行 |

通知新增独立队列zx.notifications和死信zx.notifications.dead，AUTO确认发生在事务用例返回后；CLI新增ZX_REPLAY_QUEUE白名单以恢复指定通知或统计事件，仍要求真实管理员会话和恢复权限。

文档预览决策调整：首版采用即时、有界PDF响应（最多20MiB），不保存公共转换缓存，暂不新增持久副本表。API转换前后均验证资产权限/版本，所有外部IO在事务外；OkHttp调用总超时90秒、读取65秒，转换器Office任务60秒。高并发持久副本属于后续扩展，不能将本次视为已实现。

kkFileView采用v5.0.3 Office专用裁剪构建，复用固定commit的OfficePluginManager、LocalOfficeUtils和ConfigUtils并保留许可；只装配Office进程管理和私有字节接口，不包含通用网页、CAD、压缩包或视频预览功能。适配层禁止宏、外链自动更新、任意URL输入，关闭其他HTTP路径；独立无外网Docker网络、非root、只读根目录和内存/进程限制。
