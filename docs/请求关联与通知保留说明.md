# 请求关联与通知保留

## 请求关联

服务端在认证前生成UUID，响应X-Request-ID、业务错误traceId、认证拒绝traceId、同步业务审计trace_id保持一致。客户端传入的同名头不作为可信标识。异步分派复用请求属性；MDC在finally恢复，避免线程复用串号。日志级别模式包含requestId，不记录请求体、令牌和查询参数。后台任务没有HTTP上下文时审计trace_id为空。

这是HTTP关联与审计定位能力，不等同完整OpenTelemetry分布式追踪；目前没有跨模型供应商或RabbitMQ的span导出，不声称具备全链路追踪。

## 通知保留

ZX_NOTIFICATION_RETENTION_DAYS默认0关闭；显式配置30至3650天后worker每分钟执行一批。每批最多清理100条收件箱和100条已结束投递任务的标题正文；QUEUED任务不清理。多副本使用SKIP LOCKED，短事务完成。尚未最终确定业务保留期，因此本地没有启用自动清理。

清理替换为固定中文占位文案，保留收件人/事件唯一键、原始SHA-256文案摘要、时间及模板引用，不删除去重墓碑。相同事件重放不会恢复正文；不同原始文案仍报冲突。此功能不是账户匿名化/删除，不能代替个人数据全生命周期策略。账务、审计、聊天不在此清理范围。

真实数据库测试覆盖关闭、非法天数、仅清理过期已结束项、待处理保护、重复执行、正文清理后合法重放不复活及非法文案冲突。请求关联测试覆盖客户端伪造ID、错误一致性、异常清理、真实审计落库与HTTP未认证响应。

## 同机双实例验证

测试启动第二个独立Spring容器，两个随机HTTP端口共享本次隔离数据库schema。并发提交同一个幂等创建请求，两端返回同一资源；更新账户认证版本后两端均返回401；关闭第二实例后第一实例liveness仍200。68项完整测试通过。这验证共享状态而非跨主机故障、负载均衡器或容量SLA。
