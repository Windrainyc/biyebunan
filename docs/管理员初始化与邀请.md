# 管理员初始化与邀请

## 首次部署

先构建并运行数据库迁移，再在受控运维终端运行：

```sh
python3 scripts/run-local.py migrate
# 通过受保护环境注入 ZX_BOOTSTRAP_PHONE、ZX_BOOTSTRAP_NAME、ZX_ADMIN_ORIGIN。
# 不使用默认号码或默认密码，不把敏感值写入Shell历史。
python3 scripts/run-local.py bootstrap
```

初始化进程不监听HTTP；仅当数据库完全没有管理员账户时允许执行。生成的 `secrets/bootstrap-invitation.json` 权限为0600，有效24小时，禁止提交或发到日志。通过安全渠道交给目标管理员后，使用邀请令牌调用MFA登记接口，再用动态验证码和首次密码激活。激活返回管理员会话；同一动态码不能立即再次登录。已有同名输出文件时拒绝覆盖，失败时先核对数据库事务是否提交，不盲目重新初始化。唯一初始化管理员从未激活且仍停用时，可由运维设置ZX_BOOTSTRAP_RENEW=true，提供同一手机号并用ZX_BOOTSTRAP_OUTPUT指定新的受保护文件后再运行bootstrap。重发立即作废旧邀请。已激活账户、其他来源账户或存在多个管理员时一律拒绝，不能用来绕过MFA。

此命令没有在本地真实app库创建账户；自动化测试在随机隔离schema真实运行bootstrap，验证首次初始化、重发、已激活拒绝，同时验证邀请、MFA和激活，不产生真实用户。

## 后续账户分配

1. `POST /api/v1/admin/users` 分配管理员或中介，返回DISABLED账户。
2. `POST /api/v1/admin/users/{id}/invitations` 发邀请，必须携带新的Idempotency-Key。重复同键返回同一链接；更换幂等键重发会使旧链接失效。
3. 中介可使用 `POST /api/v1/admin/partner-invitations` 一次创建账户和邀请。
4. 中介发送ACTIVATE/partner手机挑战后调用 `/api/v1/auth/partner/activate`；短信未配置返回503。
5. 管理员调用 `/api/v1/auth/admin/mfa-enrollments`，使用身份验证器登记后调用 `/api/v1/auth/admin/activate`，字段 `invitationToken/password/mfaEnrollmentId/mfaCode`。

所有秘密响应Cache-Control为no-store。不要复制令牌、二维码URI、密码到工单或请求日志。数据库仅存令牌HMAC和加密MFA材料。生产需稳定保管主密钥及备份，不能通过更换主密钥“重置”账户。
