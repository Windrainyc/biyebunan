# 用量核对与私聊审计说明

## 原调用证据与核对

V34的run_usage_evidence保存原调用返回的实际用量或明确无费用结果。完成事务验证原owner、generation和已持久化call_started_at，随后追加证据；未开始调用、伪造执行器和冲突证据不能成为核对依据。证据没有公开写入口，不含提示词或回答正文，禁止修改删除。

运行取消或过期后的迟到返回不重新发布回答、不修改对话终态，只保存可供核对的用量证据。正常成功结算也保留同一证据，重复相同返回幂等；冲突返回报错，不覆盖原值。

POST /api/v1/admin/runs/{id}/reconcile要求billing:reconcile、原因和幂等键，仅对RECONCILING创建任务。已有排队任务复用，重复HTTP键返回原响应。任务加入独立billing_reconciliation_task和operational_job联合视图，可从现有管理任务接口查询。

独立worker每次处理一个任务，按账户→运行→核对任务顺序加锁复查。处理只有数据库操作，在一个短事务内核对证据、追加结算或释放账本、结束任务、写审计/outbox。进程崩溃回滚后仍可处理；多节点竞争不会重复结算。它不调用模型、不重新发送付费请求，也不要求跨系统exactly-once。

有USAGE证据按运行固定价格结算，有NO_CHARGE证据释放冻结。没有可信证据则任务FAILED，errorCode=PROVIDER_RECONCILIATION_UNAVAILABLE，保留RECONCILING额度。日后证据到达可重新创建核对任务，不通过通用扫描任务重试接口恢复。

当前只支持核对原调用返回的持久证据。供应商账单查询API适配、管理员人工证据裁决尚未实现，不能把这里的失败状态视为已完成全部供应商核对。原通用Chat Completions协议并不保证存在请求ID用量查询接口，未配置能力时不能伪造查询成功。

## 管理员私聊审计

GET /api/v1/admin/conversations及/{id}/messages要求chat:audit和1至1000字符原因。服务层重新查当前权限，查询与访问审计同事务，审计写失败不返回正文。响应Cache-Control:no-store，审计记录只保存理由和目标，不复制提示、回答或搜索正文。

目录含用户隐藏会话，消息审计含历史引用，即使知识已撤回；这是专门审计权限的取证范围。普通学生读取仍检查当前来源授权，中介仍完全禁止读取私聊。角色与审计权限的配置应按最小授权管理。

status筛选不适用于会话或消息，传入拒绝；目录q匹配标题，历史q匹配正文。消息不可更新，updatedAt排序使用createdAt。未实现审计资料保留期自动销毁，后续应与账务留存要求一起制定。

## 前台教育字典与中介学生

学生/中介分别提供schools、majors分页，只返回启用院校及启用院校下的启用专业。status=DISABLED返回空。专业新增可选schoolId过滤，与OpenAPI1.0.12同步。

中介学生列表和详情由当前actor.id关联software_order.partner_id，必须有非取消订单已绑定该学生。activeOrderCount仅计算本中介的CONFIRMED/ACTIVE订单，不包含其他中介订单。取消全部关系或迁移归属后再次查询失效；只返回昵称、脱敏手机、个人资料院校名和订单数，不返回角色、私聊、文件地址。个人院校未设置时schoolName为null。该只读聚合详情没有可更新ETag，已修订开发契约。
